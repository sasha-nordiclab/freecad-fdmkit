# Known FreeCAD issues

One dated line per critical FreeCAD failure met through fdmkit: call, documents, symptom, workaround.

- 2026-11-07: FreeCAD 27.1 (build 20261027) crashed in `reopen()` of BottleFrame while Panterla, JoboBottle,
  StorageBox and Purchased were open and BottleFrame had just gained cross-document params
  (`JoboBottle#params...`). The file was saved before the crash; unsaved Panterla joint expression edits were lost.
  Workaround: save dependent documents (`doc.save()`) before `reopen()`; restart FreeCAD and reopen Panterla.
- 2026-11-08: FreeCAD 27.1 segfault in `TechDrawGui.exportPageAsSvg` → `QGSPage::saveSvg` →
  `ViewProviderPage::setTemplateMarkers` (ORWO 828, page Dwg03). The page had been opened with `doubleClicked()` in an
  earlier run() call and its MDI scene had been probed (`findChildren(QGraphicsView)`, repeated `doubleClicked()`);
  the export came in a later call without reopening. Nothing lost (model saved/committed).
  Workaround: open the page (`doubleClicked()`), `Gui.updateGui()` and export in the SAME call (as `ink()` /
  ORWO `export_drawing` do); never probe or keep page scenes across calls.
- 2026-11-08: the TechDraw page's GUI scene (`<Page>View` QGraphicsView, `TechDrawGui.getSceneForPage`) is not a
  reliable source of geometry: on frozen pages (`KeepUpdated=False`) it keeps dimension graphics from an older state
  after views move, empties when the tab is hidden, and `getSceneForPage` returned 0 items. `exportPageAsSvg` builds
  its own up-to-date scene. Workaround: measure the exported SVG (`drawing.ink()` / `sheet_fit()`), not the GUI scene.
- 2026-11-08: frozen TechDraw pages (`KeepUpdated=False`) export stale dimension lines after their views were moved
  (`view_layout`): `dim_check` passes (object data) while the SVG shows dims at old places. Workaround: `page_sync()`
  (KeepUpdated on, touch dims/annotations, recompute) one call before export / `sheet_fit`.
- 2026-11-08: after reopening the ORWO document, frozen pages Dwg10/11/12 had empty view caches (0 visible edges)
  and exported blank views. Workaround: refresh the page (KeepUpdated on, recompute) and assert
  `getVisibleEdges()` is non-empty before export.
- 2026-11-08: on load, CAM ToolBits report `PropertyPythonObject::toString(): failed for ToolBitEndmill` and

## Non-critical errors (cause and how to avoid)

From 2026-11-15 every error an fdmkit call produces is logged here, not only crashes: symptom, cause, workaround.

- 2026-11-15: `RPC ERR GUI dispatch gave up after 120.0s ... mouse buttons held (3D navigation drag)` on a read-only `?sel()` (Panterla). Cause: the user was rotating the view; the GUI thread does not run queued tasks while a mouse button is held. Workaround: retry once after a pause, never queue a second call meanwhile; the timeout stays in the Report view as an error although nothing failed.
- 2026-11-15: MotorHousing `Box`, `PartDesign::Fillet` on all nine edges of the `WireRib` pad (lengthwise + top end + floor coves, R0.8): feature "Up-to-date" but `Shape.isValid()` False and volume +104 mm³ instead of about +6; with the top-end edges only: `StdFail_NotDone` / null shape; a chamfer on the top-end outline fails the same way. Cause: OCC cannot blend convex and concave fillets meeting at one vertex on a 1.8 mm thick rib (radius sum equals the face height at the corners). Workaround: fillet only the lengthwise edges; shape the end in the sketch. Always dry-run the edge set first in a read-only call (`?` + `shape.makeFillet(r, edges)` in try/except, check `isValid()` and the volume change) and create the feature only for a set that passed.
- 2026-11-15: a `run()` batch that printed from `exec`/`print` and ended in `check: ERR` was NOT rolled back: the invalid Fillet stayed in the tree, the next attempt was stacked on it (`WireRibRound001`), and every Box feature from `InsertLeadIn` on reported `isValid()` False until the next parameter recompute. Cause: only a raised ERR step rolls a batch back; a `check()` ERR result is just text, and "the active document changed during the call" also disables rollback. Workaround: after any ERR inspect the tree (`Tip`, new objects) before the next edit; remove leftovers per rule 11 (clear expressions, recompute, removeObject, restore `Tip`); judge validity after a clean recompute.
- 2026-11-15: `FeatureDressUp.cpp(295): Invalid edge link: ...Edge258` / `...Edge256` (MotorHousing `WireRibRound`, three times) after changing `s_wgr` constraints and `mb_side`. Cause: the dress-up names edges of `pocket016`; lengthening the rib or moving the wall renumbers them, and the recompute inside `P()` hits the stale name. Workaround: in the same call set `Suppressed = True` on dress-ups that reference the changed region, change the parameter, re-pick the edges geometrically (curve type + bounding box), set `Base`, unsuppress, recompute once. Afterwards compare each dress-up's volume change with the expected one: a silently remapped edge leaves a valid solid.
- 2026-11-15: `Gui.getDocument('StorageBox').ActiveView` is None (`'NoneType' object has no attribute 'setActiveObject'`) with Panterla as the visible document. Cause: a document opened as a link dependency has no 3D view, so the active-Body helpers (`sk`, `circ`, `pad`) cannot target it. Workaround: build with the raw API on the named Body (`body.newObject('Sketcher::SketchObject', ...)`, `addGeometry`, named constraints with expressions, `body.newObject('PartDesign::Pocket', ...)`); `P()` and `check()` work after `App.setActiveDocument(name)`.
- 2026-11-15: `cad/check.py validate()` failed with `RivetToolBody: drilling tools must stay hidden` after an edit and `check()` in StorageBox. Cause: `RivetToolBody.Visibility` was True (not established whether the edit session or an earlier GUI action turned it on). Workaround: set `RivetToolBody.Visibility = False` and save StorageBox before `validate()`.
- 2026-11-15: plain `check()` in StorageBox reports `Box x LeftClampSpacer`, `RivetToolBody: 9 solids` and similar. Cause: local-origin Bodies overlap at the origin and the tool body is a compound by design; not a model fault. Workaround: judge StorageBox by the feature's validity and volume change, then by `cad/check.py validate()` in Panterla.
- 2026-11-15: MotorHousing `Box` and StorageBox `Box` turned default gray (0.68, 0.71, 0.74) in Panterla after features were added with the raw API (`body.newObject('PartDesign::Fillet'/'Chamfer'/'Pocket', ...)`: `WireRibRound`, `HingeBlockChamfer`, `ConnectorHoles`). Cause: a Body is drawn with its Tip feature's appearance; a feature created by `newObject` gets the default colour, not the Body's (the Body's own ShapeColor stays right, so reading it shows nothing wrong). Workaround: right after creating any feature that becomes the Tip copy `ShapeAppearance` and `Transparency` from the Body's ViewObject to the feature's, then save; verify with the Tip's ShapeColor, not the Body's. A link's view provider has no `ShapeMaterial` (AttributeError on a read probe): read colours on the source Body/Tip.
- 2026-11-15: MotorHousing `s_mlgk` (rectangle with `fil()` corners): `delGeometries` of a corner arc together with its two construction stubs left the side lines unconstrained in direction, dropped the named radius constraints `f1_r`…`f4_r` with their expressions, and the pad went null (`check()` then raised `FloatingPointError: Invalid bounding box argument`). Cause: after `fil()` the Horizontal/Vertical constraints live on the corner stubs, the trimmed sides only hang on them by tangency. Workaround for a square corner: clear the arc's radius expression, delete the arc only, `toggleConstruction` both stubs into real geometry and fix their length (`Equal` to another stub); dry-run in a `?` call and compare the wire edge counts and volume first.
- 2026-11-15: `PartDesign::SubShapeBinder` on two nested sketches (`s_out` + `s_cav`) with `MakeFace=True` gives two overlapping faces, so a Common pocket keeps the whole outer area (4543 instead of 456 mm³). Workaround: `MakeFace=False`; the pocket then builds one face with a hole from the two wires.
- 2026-11-15: moving chained dress-ups (Box `InsertLeadIn` → `CornerRound` → `BedChamfer` → `PanelEdgeRound`) to the end of the Body with `body.removeObject` + `insertObject` in one call: the Tip kept the dress-up geometry after `recompute()` (volume unchanged), so geometric re-picking matched nothing and the re-inserted features gave wrong volumes (dry-run only, nothing saved).
